# Система обработки XML-файлов

## Описание задачи

Разработана система для обработки XML-файлов на основе микросервисной архитектуры. Система состоит из двух взаимодействующих сервисов, использующих RabbitMQ для обмена сообщениями и SQLite для хранения данных.

## Технологии и инструменты

*   **Язык:** C# (.NET 8.0)
*   **База данных:** SQLite (встроенная, файловая)
*   **Брокер сообщений:** RabbitMQ
*   **Работа с БД:** Entity Framework Core 8

## Архитектура системы

Система состоит из двух независимых микросервисов:

### 1. FileParserService
*   **Назначение:** Отслеживает указанную директорию на наличие XML-файлов.
*   **Функционал:**
    *   Сканирует директорию с интервалом в 1 секунду.
    *   Обрабатывает каждый найденный файл в отдельном потоке.
    *   Парсит XML-файл, десериализуя его в структурированные C#-объекты.
    *   Для каждого модуля случайным образом изменяет свойство `ModuleState` (возможные значения: `Online`, `Run`, `NotReady`, `Offline`).
    *   Формирует сообщение и публикует его в RabbitMQ через MassTransit.
*   **Отказоустойчивость:**
    *   **Невалидные XML-файлы:** При ошибке парсинга или обработки файл не удаляется, а перемещается в специальную "карантинную" директорию `_error` для последующего анализа.
    *   **Недоступность RabbitMQ:** При невозможности отправить сообщение обработка файла прерывается, и он остается в исходной директории. Сервис повторит попытку обработки через 1 секунду, обеспечивая механизм повторных попыток.

### 2. DataProcessorService
*   **Назначение:** Получает данные о состоянии модулей и сохраняет их в базу данных.
*   **Функционал:**
    *   Подписывается на сообщения из RabbitMQ.
    *   При получении сообщения сохраняет или обновляет (Upsert) записи в базе данных SQLite.
    *   Для каждой записи сохраняются поля `ModuleCategoryID` и `ModuleState`.
    *   При обновлении существующей записи по `ModuleCategoryID` изменяется только `ModuleState`.
*   **Отказоустойчивость:**
    *   **Недоступность RabbitMQ:** MassTransit автоматически обрабатывает потерю и восстановление соединения с брокером.

## Настройка и запуск для локальной разработки

### Шаг 1: Предварительные требования

#### Основные инструменты (обязательно для обоих сценариев)

*   [.NET 8.0 SDK](https://dotnet.microsoft.com/download)
*   [Git](https://git-scm.com/downloads)
*   Инструмент для просмотра SQLite (например, [DB Browser for SQLite](https://sqlitebrowser.org/))

#### Требование RabbitMQ (Выберите **один** из следующих двух вариантов)

##### Вариант 1: Использование Docker (Рекомендуемый)
Этот способ является предпочтительным, так как он не требует установки RabbitMQ и его зависимостей (Erlang) непосредственно в вашу систему.

*   [Docker Desktop](https://www.docker.com/products/docker-desktop)

##### Вариант 2: Локальная установка на Windows
Этот способ подходит, если вы не можете или не хотите использовать Docker.

*   **RabbitMQ Server**: Следуйте [официальной инструкции по установке на Windows](https://www.rabbitmq.com/install-windows.html).
    
    **Важно:** Для работы RabbitMQ требуется предварительная установка **Erlang**. Ссылки на нужную версию Erlang есть в инструкции.

### Шаг 3: Настройка конфигурационных файлов

Система использует файлы `appsettings.Development.json` для локальной разработки. Вам необходимо указать пути к рабочим директориям.

1.  **Настройка `FileParserService`**:
    *   Откройте файл `FileParserServiceSln/FileParserService/appsettings.Development.json`.
    *   Измените пути в секции `FileWatcher` на актуальные для вашей системы:
        ```json
        "FileWatcher": {
          "Path": "C:\\Path\\To\\Your\\Input_Folder",
          "ErrorPath": "C:\\Path\\To\\Your\\Input_Folder\\_error"
        }
        ```
    *   **Создайте эти папки** на вашем компьютере.

2.  **Настройка `DataProcessorService`**:
    *   Откройте файл `DataProcessorServiceSln/DataProcessorService/appsettings.Development.json`.
    *   Измените путь в `ConnectionStrings` на место, где вы хотите хранить файл базы данных:
        ```json
        "ConnectionStrings": {
          "DefaultConnection": "Data Source=C:\\Path\\To\\Your\\Database_Folder\\instrument_status.db"
        }
        ```
    *   **Создайте папку** для хранения БД. Сам файл будет создан автоматически.

### Шаг 4: Создание базы данных

Перед первым запуском необходимо создать файл SQLite и применить к нему схему данных (миграцию).

P.S. В репозитории уже лежит готовый файл базы

1.  Откройте терминал.
2.  Перейдите в папку проекта `DataProcessorService`:
    ```bash
    cd DataProcessorServiceSln/DataProcessorService
    ```
3.  Выполните команду для создания миграции (если папки `Migrations` еще нет):
    ```bash
    dotnet ef migrations add InitialCreate
    ```
4.  Выполните команду для создания и обновления базы данных:
    ```bash
    dotnet ef database update
    ```
    После этого по пути, указанному в `ConnectionStrings`, появится файл `instrument_status.db`.

---

### Шаг 5: Запуск системы

Выберите сценарий запуска в зависимости от того, как у вас установлен RabbitMQ.

#### Сценарий A: Запуск с RabbitMQ в Docker-контейнере

1.  **Запуск RabbitMQ**:
    *   Убедитесь, что Docker Desktop запущен.
    *   В терминале в **корневой папке проекта** (где лежит файл `docker-compose.yml`) выполните команду:
        ```bash
        docker-compose up -d
        ```
        * `-d` запустит контейнер в фоновом режиме.
    *   Проверить статус RabbitMQ можно в браузере по адресу `http://localhost:15672` (логин/пароль: `guest`/`guest`).

2.  **Запуск сервисов** (порядок важен):
    *   **Сначала запустите `DataProcessorService`**. Откройте новый терминал, перейдите в папку проекта и выполните `dotnet run`.
    *   **Затем запустите `FileParserService`**. Откройте еще один терминал, перейдите в его папку и выполните `dotnet run`.

3.  **Остановка RabbitMQ** (когда закончили работу):
    *   В терминале в корневой папке проекта выполните команду:
        ```bash
        docker-compose down
        ```

#### Сценарий Б: Запуск с локально установленным RabbitMQ

1.  **Запуск RabbitMQ**:
    *   Убедитесь, что служба RabbitMQ запущена на вашем компьютере. Это можно проверить одним из способов:
        *   **Через командную строку (от имени администратора):**
            ```bash
            rabbitmq-diagnostics status
            ```
            Вы должны увидеть сообщение, что RabbitMQ запущен.
        *   **Через службы Windows:** Нажмите `Win+R`, введите `services.msc`, найдите в списке службу `RabbitMQ` и убедитесь, что ее состояние — "Выполняется".

2.  **Запуск сервисов** (порядок важен):
    *   **Сначала запустите `DataProcessorService`**. Откройте новый терминал, перейдите в папку проекта и выполните `dotnet run`.
    *   **Затем запустите `FileParserService`**. Откройте еще один терминал, перейдите в его папку и выполните `dotnet run`.
    *   *Сервисы автоматически подключатся к вашему локальному RabbitMQ, так как в `appsettings.Development.json` указан `HostName: "localhost"`.*

### Шаг 6: Тестирование

1.  Поместите один или несколько XML-файлов в папку, которую отслеживает `FileParserService`.
2.  **Ожидаемый результат:**
    *   Файл(-ы) исчезнут из папки `input`.
    *   В логах `FileParserService` появятся сообщения об отправке данных.
    *   В логах `DataProcessorService` появятся сообщения о получении и сохранении данных.
    *   С помощью DB Browser for SQLite откройте файл `instrument_status.db` и убедитесь, что в таблице `ModuleStatuses` появились или обновились записи.
    *   При помещении невалидного XML-файла он будет перемещен в папку `_error`.

### Исходный код

Исходный код организован в виде двух независимых решений (`.sln`), каждое со своим проектом. Также имеется общая библиотека классов `SharedContracts` для обмена сообщениями.

-   `FileParserServiceSln/` - Решение для сервиса-парсера.
-   `DataProcessorServiceSln/` - Решение для сервиса-обработчика данных.
-   `SharedContracts/` - Библиотека с контрактами сообщений для MassTransit.
